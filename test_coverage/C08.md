# C08 Test Coverage

## Scope

This document describes behavioral coverage for `mini-moul/tests/C08`.
The goal is to ensure each C08 exercise fails by non-zero exit status when
subject requirements are violated, instead of relying on compile-only smoke
checks.

## Runner Dependencies

- `norminette -R CheckDefine` is used for `C08/ex01` and `C08/ex02`.
- The runner injects evaluator include directories during compilation:
  - `C08/ex04`: `tests/C08/ex04`
  - `C08/ex05`: `tests/C08/ex05/resources`
- This allows subject-compatible student files that contain
  `#include "ft_stock_str.h"` to compile without requiring students to submit
  that header.

## Exercise Behavior Coverage

### ex00 (`ft.h`)

- Includes `ft.h` twice to validate re-inclusion safety.
- Validates exact function signatures by binding declarations to typed function
  pointers.
- Provides local dummy definitions only for linking.
- Fails on missing declarations, wrong return types, wrong parameter types, and
  comment-only headers.
- Whitespace/layout in header declarations is ignored (compile-based check).

### ex01 (`ft_boolean.h`)

- Asserts exact macro values:
  - `TRUE == 1`
  - `FALSE == 0`
  - `SUCCESS == 0`
- Asserts `EVEN` behavior for `0`, `1`, `2`, `-2`, and `-3`.
- Asserts exact message literals including trailing newline:
  - `EVEN_MSG`
  - `ODD_MSG`
- Asserts `t_bool` can store `EVEN(...)` results.

### ex02 (`ft_abs.h`)

- Validates base values: `ABS(5)`, `ABS(-5)`, `ABS(0)`.
- Validates expression behavior to catch parenthesis bugs:
  - `ABS(2 - 5) == 3`
  - `ABS(-3) * 2 == 6`
  - `10 / ABS(-2) == 5`
  - `ABS(-(7)) == 7`

### ex03 (`ft_point.h`)

- Includes header twice to validate re-inclusion safety.
- Verifies `t_point` usability and field accessibility.
- Runtime-checks `set_point` writes expected values to `x` and `y`.

### ex04 (`ft_strs_to_tab.c`)

- Validates normal behavior:
  - non-NULL result for valid input
  - each entry preserves order
  - `size == strlen(av[i])`
  - `str` pointer identity matches input pointer
  - `copy` is allocated, non-NULL, and string-equal to source
  - `copy != str` (deep copy)
  - sentinel exists at `result[ac].str == 0`
  - mutating `copy` does not mutate original `str`
- Strict `ac == 0` behavior:
  - requires non-NULL result
  - requires `result[0].str == 0`
- Simulates `malloc` failure on each allocation call:
  - requires function returns `NULL`
  - requires already allocated memory is freed (no tracked live allocations)

### ex05 (`ft_show_tab.c`)

- Includes student `ft_show_tab.c` and verifies runtime output.
- Captures `stdout` via `pipe` + `dup`/`dup2` + `read`.
- Compares exact output bytes against expected strings for:
  - single-entry case: `hi`, `2`, `HI`
  - multi-entry case: includes empty string and multi-digit size
- Sentinel behavior is verified by placing extra data after sentinel and
  asserting output stops at `.str == 0`.

## Strictness Decisions

- `ex04 ac == 0` is strict: only non-NULL sentinel array passes.
- `ex04` allocation-failure paths are mandatory and leak-checked.
- `ex05` uses exact byte-for-byte output matching.

## Non-goals / Known Limits

- `ex05` validates stdout content only; it does not attribute failures to a
  specific helper implementation strategy.
- `ex04` leak tracking is based on wrapped `malloc`/`free` calls inside the
  included student source path.
